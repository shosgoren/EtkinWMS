# T-1093 — Yeni cariye otomatik kod (türe göre MUS / TED / CAR)

**Dal:** `feat/T-1093-cari-otomatik-kod`
**Amaç:** Kullanıcı bulgusu (27 Ekim, iPhone): cari için kod otomatik atanmıyor. Kullanıcı kararı: türe göre önek — müşteri `MUS-0001`, tedarikçi `TED-0001`, ikisi `CAR-0001`; kullanıcı isterse değiştirir.
**Dokunulacak dosyalar:** `docs/tasks/T-1093.md`, `docs/changes/T-1093.md`, `packages/domain/src/catalog/code-suggest.ts`, `apps/web/app/t/*/parties/actions.ts`, `apps/web/app/t/*/parties/parties-view.tsx`, `tests/integration/catalog/party-code-suggest-action.int.test.ts`, `tests/e2e/zz-kural.spec.ts`.
**Kapsam:**
- Domain `suggestCode` yeni tür `party` (SALT OKUMA, `settings.manage`): sıra cari `code_key` (büyük harf, benzersizlik anahtarı) üzerinden, tenant filtreli; varsayılan önek MUS, 4 basamak. `PARTY_CODE_PREFIX` tür → önek.
- Eylemler: `suggestPartyCodeAction({ slug, kind })` (önek sunucuda türden seçilir; istemci serbest önek gönderemez). `savePartyAction` `autoCode` beyanı: yalnız yeni caride ve kod sunucu önerisi biçimindeyse `CODE_TAKEN`ta aynı önekle sıradakine geçer (en çok `SUGGEST_RETRY_MAX`); elle yazılan kod asla sessizce değişmez (ürün/depo kuralı, T-259).
- Form: yeni caride kod kendiliğinden dolar, tür değişince yenilenir; kullanıcı kodu değiştirirse (silmek dahil) öneri bir daha uygulanmaz; önerilen kod "kaydedilmemiş değişiklik" sayılmaz.
**Kapsam dışı:** Excel aktarımında kodsuz satıra otomatik kod; var olan carilerin kodunu değiştirme.
